📌 1. Notación de Kendall y los 5 Elementos de un Sistema de Simulación

Notación Estándar A / B / c:

  • A (Llegadas): Distribución de tiempos entre arribos (M = Exponencial / Proceso de Poisson con tasa media λ).
  • B (Servicio): Distribución de tiempos de atención (M = Exponencial con tasa media μ).
  • c (Canales): Cantidad de servidores o puestos idénticos en paralelo (c ≥ 1) con fila única.
  • Disciplina: FIFO (First-In, First-Out), capacidad ilimitada y sin abandonos.

Los 5 Elementos de Simulación:

  • Entidades: Clientes, paquetes, vehículos o llamadas que fluyen por el sistema.
  • Atributos: Hora de llegada, tipo de trámite o prioridad de la entidad.
  • Actividades: Proceso de atención de duración estocástica en el servidor.
  • Estados: Condición actual (Servidor Libre/Ocupado, Longitud de cola n).
  • Eventos: Instantes que alteran el estado (Arribo, Inicio servicio, Fin servicio).
📐 2. Fórmulas Matemáticas Oficiales (M/M/1 y M/M/c)

Modelo M/M/1 (Cola Simple):

• Intensidad de uso: ρ = λ / μ < 1

• Probabilidad de ocio: P₀ = 1 - ρ

• Probabilidad de esperar en fila: P(esperar) = ρ

• Longitud media de cola: Lq = ρ² / (1 - ρ)

• Clientes en sistema: L = ρ / (1 - ρ) = Lq + ρ

• Tiempo medio en cola: Wq = Lq / λ

• Tiempo medio en sistema: W = Wq + 1/μ

Modelo M/M/c (Servidores en Paralelo):

• Intensidad de tráfico: r = λ / μ | Utilización: ρ = r / c < 1

• Probabilidad de sistema vacío (P₀):

$$P_0 = \left[ \sum_{n=0}^{c-1} \frac{r^n}{n!} + \frac{r^c}{c!(1 - \rho)} \right]^{-1}$$

• Probabilidad de esperar (Fórmula C de Erlang):

$$P(\text{esperar}) = P(n \ge c) = \frac{r^c}{c!(1 - \rho)} \cdot P_0$$

• Longitud de cola: Lq = P(n ≥ c) · ρ / (1 - ρ)

• Tiempos medios: Wq = Lq / λ | W = Wq + 1/μ

🚀 3. Mini Guía FlexSim 2026: ¿Cómo modelar, cuántos días simular y contrastar con la teoría?
🎯 Objetivo en el Laboratorio:

Contrastar los resultados numéricos obtenidos en las fórmulas analíticas (M/M/1 y M/M/c) con una simulación estocástica en FlexSim 2026 para validar el comportamiento del sistema real antes del Trabajo Final.

🚨 ¡ALERTA TEÓRICA Y ERROR CLÁSICO EN FLEXSIM!: ¿Por qué si el problema dice "Poisson" se DEBE elegir "Exponential"?
1. En el Source (Llegadas λ):

• Enunciado Teórico: "Llegadas con proceso de Poisson de tasa λ". Mide el conteo discreto de paquetes/hora (cuántos llegan por unidad de tiempo).

• FlexSim (Inter-Arrival Time): El simulador pide el tiempo continuo transcurrido entre un arribo y el siguiente (Δt).

• Demostración Estocástica: Si el conteo de llegadas es Poisson(λ), el tiempo entre arribos consecutivos es estrictamente EXPONENCIAL(λ) con media 1 / λ.

⚠️ ¡NUNCA selecciones poisson en el desplegable de FlexSim! Si eliges Poisson con media 18, FlexSim esperará ~18 horas discretas entre cada entidad. Selecciona SIEMPRE Exponential con Scale = 1/λ.

2. En el Processor (Servicio μ):

• Enunciado Teórico: "Tiempo de servicio sigue una distribución exponencial con tasa media μ" (o tiempo medio 1/μ).

• FlexSim (Process Time): Mide la duración que el servidor retiene una entidad en estado Processing.

• Configuración: Selecciona también Exponential y en Scale ingresa el tiempo medio de atención 1 / μ.

💡 Regla Mnemotécnica de Cátedra: En FlexSim, tanto para el Source como para el Processor, se utiliza SIEMPRE la distribución Exponential cargando Scale = 1 / Tasa.

Paso 1 Configuración del Source (Llegadas λ) Entrada

1. Selecciona el Source → mira el panel lateral derecho Properties.

2. En la sección Source, verifica que Arrival Style esté en Inter-Arrival Time.

3. En Inter-Arrival Time, haz clic en el botón desplegable → Statistical Distribution → Exponential (¡No Poisson!).

4. Expresión cargada: exponential(location, scale, stream) con location = 0.

⚠️ ¡Cuidado con la división entera en FlexSim!: Si escribes 1/18, FlexSim hace división entera entre enteros (1 / 18 = 0), lo que genera Scale = 0 y da el error "Could not generate sample data".

• Solución: Escribe siempre el número con decimales: 0.0556 (o 1.0 / 18). O mejor aún, usa la unidad del modelo (ej: 200 segundos o 3.3333 minutos).

• Valores a ingresar en Scale según la unidad de tiempo del modelo:
Modelo en Segundos (Por defecto):

Scale = 3600 / λ

18 paq/h → ingresar 200

Modelo en Minutos:

Scale = 60 / λ

18 paq/h → ingresar 3.3333

Modelo en Horas:

Scale = 1.0 / λ

18 paq/h → ingresar 0.0556

Paso 2 Configuración del Processor (Servicio μ) Servidor

1. Selecciona el Processor → mira la sección Processor en el panel Properties.

2. Max Content: 1 (1 entidad a la vez por servidor en paralelo).

3. Setup Time: 0 (sin tiempo previo de preparación).

4. Process Time: Cambia de constante a → Statistical Distribution → Exponential.

5. Expresión: exponential(0, scale, getstream(current)) con Scale = 1/μ.

• Valores a ingresar en Scale según la unidad de tiempo del modelo:
Modelo en Segundos (Por defecto):

Scale = 3600 / μ

24 paq/h → ingresar 150

Modelo en Minutos:

Scale = 60 / μ

24 paq/h → ingresar 2.5

Modelo en Horas:

Scale = 1.0 / μ

24 paq/h → ingresar 0.0417

Paso 3 Configuración de la Queue (Multicanal M/M/c) Buffer FIFO

1. Conecta la Queue a cada uno de los c Processors en paralelo mediante puertos de salida (tecla 'A').

2. Selecciona la Queue → mira la sección Output en el panel derecho Properties.

3. En el campo Send To Port, haz clic en el desplegable y selecciona: Round Robin > Round Robin if Available.

💡 Justificación de Ingeniería (¿Por qué esta regla?):

• Balanceo de Carga (Load Balancing): La opción por defecto First Available siempre satura el Puerto 1 (Processor 1) dejando ociosos a los demás. Round Robin distribuye la carga en forma equilibrada (ρ1 ≈ ρ2 ≈ ρ).

• Principio "Work-Conserving": La variante "if Available" asegura que si el servidor de turno está ocupado, la entidad pasa de inmediato al canal que esté libre, evitando colas artificiales y respetando estrictamente la disciplina M/M/c.

Paso 4 Régimen Permanente y Warm-up Time Estabilidad

⚠️ Duda frecuente: "¿Por qué si simulo 1 hora o 1 día no coinciden los datos con la teoría?" Las fórmulas analíticas calculan el Régimen Permanente (t → ∞). Al iniciar en t = 0, el modelo arranca completamente Vacío y Ocioso (Empty & Idle), sesgando los promedios.

📍 Configuración en la Barra Superior (junto a Run Time):

1. Clic en la flechita desplegable (▼) al lado de la casilla Run Time.

2. Activa Warmup Time e ingresa 24.00 horas (1 día para purgar el transitorio).

3. Activa Stop Times e ingresa 168.00 (7 días) o 336.00 (14 días).

Efecto: A las 24 horas, FlexSim resetea las estadísticas en limpio y mide puramente el régimen permanente.

Demostración Paso a Paso para la Clase

Estos dos ejercicios están diseñados para ser resueltos en vivo en la pizarra durante la clase teórica-práctica. Explican la transición desde una cola simple de servidor único (M/M/1) hacia un sistema multicanal en paralelo (M/M/2).

Demo 1 • Cola Simple M/M/1

Caso: Cafetería Universitaria "Byte & Coffee" (Terminal Express)

Parámetros: λ = 30 clientes/h, μ = 40 clientes/h (ts = 1.5 min).

1. Cálculos de Ocupación:

• Utilización: ρ = 30/40 = 0.75 (75%).

• Ocio del cajero: P₀ = 1 - 0.75 = 0.25 (25%).

• Probabilidad de esperar en fila: P(esperar) = ρ = 0.75 (75%).

2. Longitudes y Tiempos:

• Cola media: Lq = 0.75² / (1 - 0.75) = 2.25 clientes.

• Clientes en local: L = 0.75 / 0.25 = 3.00 clientes.

• Tiempo en cola: Wq = (2.25 / 30) × 60 = 4.50 minutos.

• Tiempo total: W = 4.50 + 1.50 = 6.00 minutos.

Demo 2 • Cola Múltiple M/M/2

Caso: Centro de Control de Calidad "TechQuality"

Parámetros: λ = 20 lotes/h, μ = 15 lotes/h por inspector, c = 2 inspectores en paralelo.

1. Intensidad y Probabilidad de Ocio:

• Carga de tráfico: r = 20 / 15 = 1.3333 Erlangs.

• Utilización por inspector: ρ = 1.3333 / 2 = 0.6667 (66.7%).

• Término 1: ∑ rn/n! = 1 + 1.3333 = 2.3333.

• Término 2: r² / [2!(1 - ρ)] = 1.3333² / (2 × 0.3333) = 2.6667.

• P₀ = [2.3333 + 2.6667]-1 = 1 / 5 = 0.2000 (20%).

2. Indicadores Operativos (Erlang C):

• Probabilidad de esperar: P(n ≥ 2) = 2.6667 × 0.20 = 0.5333 (53.3%).

• Cola media: Lq = 0.5333 × (0.6667 / 0.3333) = 1.0667 lotes.

• Lotes en departamento: L = 1.0667 + 1.3333 = 2.4000 lotes.

• Tiempo en cola: Wq = (1.0667 / 20) × 60 = 3.20 minutos.

• Tiempo en sistema: W = 3.20 + 4.00 = 7.20 minutos.
